# Chores

Running log of simple fixes and refactors (no spec or behavior change). `- [ ] <what and why>` → `- [x]` when applied.
- [x] floor_plan: lock the room's direction only once there is enough wall (200 cells or 3 m fitted); it locked on the first 6-cell map, so an early short wall tilted every wall for the run. Regression test `test_tiny_early_map_does_not_lock_direction`.
- [x] Target labels never resolved: `name_and_id` looked profiles up by the published detector label (`can`), but `load_class_profiles` keys them by `canonical_class` (`soda can`), so every lookup missed and every target showed its raw label. The bridge now joins the two through each profile's `detector_labels`, and a profile with no `display_name` falls back to its `canonical_class` rather than the raw label. `class_profile_path` also defaults to `dome_vision_ros`'s installed `class_profiles.yaml` — the robot's own vision config, so the viewer cannot drift from what the camera image is labelled with. Proven against `f36run6`: `soda can · CN1`, `coffee cup · CP23`. Three new tests.
- [ ] static/app.js is 538 lines and panels.js 416, both over the style guide's ~300-line smell. app.js is the one to split: the floor raster and the draw* routines are a coherent half that could become map_draw.js. Not urgent, and not worth doing while F02 is about to change the view transform.
- [x] app.js: laser rays were too faint to read at `globalAlpha` 0.13; raised to 0.22 (user's call, 2026-11-15). Hit dots left at 0.6.
- [x] CLAUDE.md: the documented `rosdep install --from-paths src/dome_viz -y` cannot work — `package.xml` depends on `dome_semantic_msgs`, `dome_telemetry_msgs` and `dome_semantic`, which are workspace source packages, so rosdep tries to resolve them as apt keys and fails. Corrected to name all four paths with `--ignore-src`.
- [x] Bag replay drew no robot: the launchfile's `use_sim_time` argument collides with `better_launch`'s own switch and was never populated, and that switch alone set nothing on the node either. The launchfile now declares `sim_time` and passes it through `params`; `make replay` uses `--sim_time True`. Verified on `viz01`: robot, trail and laser all flow. `test_launch.py` guards the name and the wiring.
- [x] Makefile: `make stop` kills the bridge, the launchfile and any bag replay, and reports whether 8080 is free. The pkill patterns are bracketed so they cannot match the recipe's own shell.
